# ADR 0005: M2 identity, persistence and read-only providers

Status: Accepted implementation direction under owner M2 authorization

Keep a modular monolith and existing pure Evaluation library. Application workflows depend on tenant-aware repository/provider ports; Infrastructure supplies EF Core/Npgsql, Forge JWT verification and fixed-host HTTP adapters. API composes them. No shared Framework CRUD controllers: scoped lifecycle/version/audit rules need explicit operations. No AI-Framework dependency is useful here.

Authenticate commercial-cloud FITs against Atlassian JWKS with RS256, issuer `forge/invocation-token`, configured app audience/app.id, bounded lifetime and environment allowlist. Bind the verified app/environment/installation/cloud tuple to an explicitly provisioned tenant. Actor is the signed principal, not a request field. Operator CLI bootstraps that binding and initial administrator; it is not exposed over HTTP. Unknown installations, absent users and unsupported cloud labels fail closed. No self-selected tenant or header-supplied role.

Roles/delegations are persisted and checked per operation. Organization SystemAdministrator may manage integrations/delegation. EvaluationManager configures profiles only in exact delegated team/project scopes. Profile management does not imply private repository-read permission; explicit repository grants are required for every actor. Project/team associations are server-controlled. Profile resolution: project assignment, unique team assignment, organization default; equal-ranked different candidates fail safely.

Tenant entities use global query filters, tenant-aware relationships and save guards. Immutable metric/profile content and audit events are append-only; profile lifecycle is separate from content identity. JSON snapshots preserve full M1 contracts and canonical hashes, with a versioned reader that rejects unsupported schemas. Unique keys and optimistic concurrency reject simultaneous version/lifecycle conflicts. No hidden weight normalization or mandatory default activation. Database migrations run through an explicit operator command, not automatically on API startup.

Jira uses a Forge-forwarded opaque as-user token, verifies `/myself` matches signed actor, and performs bounded authorized GETs only against a constructed Atlassian API base derived from registered cloud identity. Never persist/log short-lived Jira bearer tokens. GitHub uses configured app key material through local secret references, generates short-lived app JWTs and requests repository-limited installation tokens with read-only permissions. Never follow redirects or arbitrary URLs from Jira/code. Pin resolved branch to a full commit SHA and reauthorize snapshot reads. HTTP failures return safe codes/retry hints, not private bodies or tokens.

Sources verified during M2 preparation: [Forge Remote contract](https://developer.atlassian.com/platform/forge/remote/essentials/), [GitHub App API](https://docs.github.com/en/rest/apps/apps), [EF tenant query filters](https://learn.microsoft.com/en-us/ef/core/querying/filters). Provider integration tests use controlled HTTP handlers and locally signed JWT fixtures; real PostgreSQL tests and live-provider smoke tests are reported separately.
